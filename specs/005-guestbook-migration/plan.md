# Plan: Guestbook migration

Spec: [./spec.md](./spec.md)

Generate one Phinx migration, `CreateGuestbook2Table`, that creates the `guestbook_2` table in a reversible `change()`. Check it with a migrate → inspect → rollback cycle that leaves the DB as it was.

## Technical context

- Phinx `0.16.12` (`app/composer.lock`). Config: `app/phinx.php` (mysql adapter, `utf8mb4`, migrations in `%%PHINX_CONFIG_DIR%%/db/migrations`, `version_order` `creation`). Do not change it.
- `app/db/migrations/` holds only `.gitkeep`, so this is the first real migration.
- Phinx commands run in the `php` container from `/app`. DB credentials come from `.env` via `docker-compose.yml`, and the DB is reachable as host `mysql`.
- `phinx create` uses the `change()` template: `declare(strict_types=1);`, `use Phinx\Migration\AbstractMigration;`, `final class CreateGuestbook2Table extends AbstractMigration`, `public function change(): void`.
- Phinx defaults this plan relies on:
  - Implicit `id` column: `int` **unsigned**, auto-increment, primary key (`FeatureFlags::$unsignedPrimaryKeys` is on by default). Do not add any `id` options.
  - Columns are `NOT NULL` unless `'null' => true` is set.
  - `string` maps to `varchar(<limit>)`.
- `GuestbookController` reads from `posts`. That table is not part of this work.

## Target structure

- Add `app/db/migrations/<timestamp>_create_guestbook2_table.php`, generated by `phinx create`
- No other files change. Keep `.gitkeep`.

## Migration

Generate the file:

```sh
docker compose run --rm php vendor/bin/phinx create CreateGuestbook2Table
```

Fill in only the body of `change()` and keep the rest of the generated template:

```php
public function change(): void
{
    $this->table('guestbook_2')
        ->addColumn('posted_at', 'datetime', ['default' => 'CURRENT_TIMESTAMP'])
        ->addColumn('name', 'string', ['limit' => 32])
        ->addColumn('email', 'string', ['limit' => 63])
        ->addColumn('message', 'string', ['limit' => 256])
        ->addIndex(['posted_at'])
        ->create();
}
```

- Keep the column order: `id`, `posted_at`, `name`, `email`, `message`.
- Index: use the default name (MariaDB names it `posted_at`). It is non-unique, so pass no `unique` option.
- Use `create()`, not `save()`, so rollback can reverse it.

## Verification cycle

Start the DB if needed with `docker compose up -d mysql`. Then:

1. `docker compose run --rm php vendor/bin/phinx status` lists `CreateGuestbook2Table` as `down`.
2. `docker compose run --rm php vendor/bin/phinx migrate`
3. `docker compose exec mysql sh -c 'mariadb -u"$MARIADB_USER" -p"$MARIADB_PASSWORD" "$MARIADB_DATABASE" -e "SHOW CREATE TABLE guestbook_2\G"'` must show:
   - `id` int unsigned NOT NULL AUTO_INCREMENT, PRIMARY KEY (`id`)
   - `posted_at` datetime NOT NULL DEFAULT current_timestamp()
   - `name` varchar(32) NOT NULL, `email` varchar(63) NOT NULL, `message` varchar(256) NOT NULL
   - `KEY posted_at (posted_at)`, which is non-unique
   - charset `utf8mb4`
4. `docker compose run --rm php vendor/bin/phinx rollback`
5. Running `SHOW TABLES LIKE 'guestbook_2'` the same way returns nothing, and `status` shows the migration as `down` again.

## Implementation order

1. Generate the migration with `phinx create`
2. Fill in `change()`
3. Run the verification cycle and end on rollback
4. Verify (see `task.md`)

## Out of scope

- Leaving the migration applied. The DB ends without `guestbook_2`.
- Changing `app/phinx.php`, `GuestbookController`, the views, routes, or the `posts` table
- Seeds, data, `README.md` or `AGENTS.md` updates
