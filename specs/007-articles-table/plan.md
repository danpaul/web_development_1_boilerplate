# Plan: Articles table

Spec: [./spec.md](./spec.md)

Generate a `CreateArticlesTable` Phinx migration, fill `change()` to create the `articles` table with its columns and indexes, run it, and verify migrate/rollback/migrate.

## Technical context

- Phinx `0.16.12` (`app/composer.lock`), config `app/phinx.php`: `development` env, `mysql` adapter, `utf8mb4`, migrations in `app/db/migrations/` (currently only `.gitkeep`).
- DB credentials come from `.env` via the `php` service `environment:` (`DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`). `.env` exists.
- Database: MariaDB (`mariadb:lts`), InnoDB, which supports FULLTEXT indexes.
- Phinx adds an implicit `id` primary key: `int unsigned`, auto increment, NOT NULL. Keep it as is (unsigned).
- Phinx columns are NOT NULL by default; `string` defaults to `varchar(255)`.

## Target structure

- Add `app/db/migrations/<timestamp>_create_articles_table.php` (generated by `phinx create`, then edited)
- No other files change

## Migration

Generate with:

```sh
docker compose run --rm php vendor/bin/phinx create CreateArticlesTable
```

Fill only `change()` (keep the generated class name, namespace-less class and `declare(strict_types=1)` / docblock as generated):

```php
public function change(): void
{
    $this->table('articles')
        ->addColumn('title', 'string', ['limit' => 255])
        ->addColumn('content', 'text')
        ->addColumn('author', 'string', ['limit' => 255])
        ->addColumn('created_at', 'datetime', ['default' => 'CURRENT_TIMESTAMP'])
        ->addIndex(['title'])
        ->addIndex(['author'])
        ->addIndex(['created_at'])
        ->addIndex(['content'], ['type' => 'fulltext'])
        ->create();
}
```

- Implicit `id` (no `'id' => false`, no `'signed'` override).
- No `null` options (all NOT NULL by default), no `addTimestamps()`, no `updated_at`.
- Index names: Phinx defaults (no `name` option).
- No `up()`/`down()`; rollback is handled by `change()` reversal.

## Verification

Query the DB with:

```sh
docker compose exec mysql mariadb -u"$DB_USER" -p"$DB_PASSWORD" "$DB_NAME" -e "<SQL>"
```

(values from `.env`; defaults `developer` / `secret123` / `developmentdb`)

- `phinx status`: `CreateArticlesTable` is `up`.
- `DESCRIBE articles`: exactly `id` (`int(10) unsigned`, PRI, auto_increment), `title` (`varchar(255)`), `content` (`text`), `author` (`varchar(255)`), `created_at` (`datetime`, default `current_timestamp()`); `Null` = `NO` for all.
- `SHOW INDEX FROM articles`: `PRIMARY` on `id`; BTREE indexes on `title`, `author`, `created_at`; `FULLTEXT` on `content`.
- `phinx rollback` (pre-approved by the user for this spec): `SHOW TABLES LIKE 'articles'` returns nothing; status shows `down`.
- `phinx migrate` again: table and indexes are back; status shows `up`.

## Implementation order

1. Ensure `mysql` is running (`docker compose up -d mysql`); `phinx status` connects.
2. `phinx create CreateArticlesTable`.
3. Fill `change()` as above.
4. `phinx migrate`.
5. Verify status, `DESCRIBE`, `SHOW INDEX`.
6. `phinx rollback`, confirm table gone; `phinx migrate`, confirm table back.
